# Gridlock rules

## Inputs
Your issue, project charter, analysis date and approved source manifest. Read the original challenge and location guide from the repository docs when resolving a rule question.

## Procedure
1. Confirm this is an authorized build task. This package was delivered as a plan: import alone does not authorize construction, spend, publication or domain purchase. Once the human starts the build, follow that scope without repeatedly asking for routine changes.
2. Work only inside `plans/plan-E/implementation/` for implementation. Keep original docs and other plans read-only. Never read Plan D. Use the configured source-docs path for inputs.
3. Preserve original owner codes, document hashes, source pages, dates and unknowns. A document publisher is not necessarily a project owner. Quarantine mixed PUBLIC/CEII pages before external processing or product use.
4. Calculate the center as the arithmetic midpoint of two located endpoints, the sole located endpoint, or null. Located means both coordinates have evidence. Compute haversine with radius 3958.8 miles. Only cross-utility distances strictly below 25 miles are overlaps. In-service date gap is secondary and is not a construction window.
5. Preserve sample IDs/labels exactly in golden mode. Production owner corrections live separately. Historical fixture results never become confirmed future opportunities by renaming their dates.
6. Use MongoDB Atlas for application data and real Gemini extraction/briefs. Separate observed facts, possible activities and hypothetical scenario inputs in all screens and claims.
7. Follow R0/R1 core, R2 target and R3 stretch gates in the project charter. Freeze features at hour 24, data at 28 and release at 30.

## Output and checks
Attach a short issue checklist naming the affected rules, sources and checks. Missing coordinates, dates and costs stay null; uncertain owners stay unresolved. Escalate contradictory source evidence with the exact page and a bounded alternative. Never silently weaken an acceptance criterion to close a task.
