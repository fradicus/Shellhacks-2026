# Track submission

## Inputs
Current event rules, QA acceptance report, deployed URL, release revision, data/model versions and human team details.

## Procedure
1. Confirm the precise ShellHacks submission links, deadlines and track eligibility with the human. Local prize notes guide the build but do not guarantee current eligibility or award terms.
2. For Sperry, gather two-utility map/list/card evidence, exact golden results, source coverage and reviewed non-sample outcomes. Explain endpoint-center approximation, unknowns and in-service semantics.
3. For Gemini, show real approved-page extraction and grounded briefs with model/timestamp and redacted request evidence. Coding with an AI agent alone is insufficient.
4. For Atlas, capture real stored sources/projects/matches, indexes and a query serving the UI. Paperclip's own database is not the application's Atlas evidence.
5. For the domain prize, obtain human-confirmed qualifying registration evidence and a working HTTPS app at the domain. Do not infer eligibility from the registrar's brand alone.
6. Script two minutes around a planner's workflow: problem, selected pair and source evidence, nearest-pair time counterexample, visible Gemini work, filing change/export, domain and next step. Use actual measured corpus/overlap counts only.
7. Separate shipped features, R2/R3 stretch outcomes and R4–R5 national/product roadmap. Capture a truthful fallback recording and label cached results. Human submits; agents prepare files and checks without accepting terms on the person's behalf.

## Output and checks
Submission draft, four-track evidence matrix, pitch script and list of unresolved requirements. Every claimed feature maps to accepted build evidence. A failed core requirement remains visible even if the roadmap is ambitious.
